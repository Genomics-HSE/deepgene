## DeepGene: схема данных и пайплайн обучения

### 1. Общая идея

Модуль `deepgene` реализует нейросетевой подход к восстановлению демографической истории (траектории эффективной численности популяции $N_e(t)$) по паттернам мутаций вдоль генома.  
Входом моделей служат бинарные профили мутаций, полученные из геномных симуляций или реальных данных, выходом — распределение по интервальным классам коалесцентного времени и производные от него оценки $N_e$ во времени.

---

### 2. Структура модуля `deepgene`

- **`deepgene/data`**  
  - `data_gen_np.py`: генерация демографий (const, human-like, zigzag, наборы set1–set3, bootleneck и др.), симуляция геномов через `msprime`, построение:
    - бинарного профиля мутаций по позиции,
    - дискретизированных локальных коалесцентных времён,
    - априорного распределения по интервалам времени.  
  - `data.py`: обёртка над генераторами данных (`DatasetXY`, `DatasetTorch`) для `pytorch_lightning`.

- **`deepgene/models`**  
  - `GruLabeler`, `LstmLabeler`, `ReformerLabeler`: модели, предсказывающие для каждого положения вдоль генома распределение по $K=32$ интервалам времени.

- **`deepgene/loss`**  
  - Набор функций потерь (кросс-энтропия, KL, EMD, CDW-CE и др.) для обучения по распределениям по интервалам.

- **`deepgene/utils`**  
  - Тренировочные и тестовые утилиты (в т. ч. `fit_model`, `test_model`, визуализация).

- **Сценарии верхнего уровня**  
  - `main.py`: запуск обучения/теста по `gin`-конфигам (`model.gin`, `data.gin`, `train.gin`).  
  - `mark_all.py`: массовая оценка обученных моделей на разных демографиях и реальных данных.  
  - `all_in_one.py`, `make_latex_table.py`: агрегация результатов `mark_all` и генерация таблиц для отчётов/статей.

---

### 3. Схема тренировочных данных

#### 3.1. Дискретизация времени и количество классов

- **Число интервалов**: `N = 32`.  
- **Границы интервалов** (`deepgene/data/data_gen_np.py`, переменная `limits`):
  - Массив длины 33, задающий разбиение по времени (в условных коалесцентных единицах / поколениях), например:
  - `[0, 700, 1500, 2200, ..., 120000, 10000000, 20000000]`.
- **Функция биннинга времени**:
  - `exponent_split(time, N) -> int`  
    Возвращает индекс интервала $k \in \{0,\dots,31\}$, в который попадает коалесцентное время `time`.

Эти интервалы используются:
- как классы для задач классификации/регрессии по распределению,  
- как базис для восстановления $N_e(t)$.

#### 3.2. Генерация демографий

Все демографии построены на базе `msprime.Demography`. Основные предопределённые сценарии (в `data_gen_np.py`):

- **`get_const_demographcs` (`const`)**: постоянный размер популяции.  
- **`get_humanlike` (`hl`)**: «человеко-подобная» история с серией узких и широких бутылочных горлышек и экспансий.  
- **`get_zigzag` (`zigzag`)**: сильно колеблющийся $N_e$ с чередованием спадов и подъёмов.  
- **Наборы `set1`, `set2`, `set3`**: смеси const / human-like / случайных траекторий / экспоненциального роста и спада и zigzag.  
- Дополнительно реализованы различные специальные демографии (bootleneck, antibootleneck, exp рост/спад и др.) для расширенных экспериментов.

#### 3.3. Симуляция генома и целевых переменных

Основной строительный блок — класс `DataGenerator` (`data_gen_np.py`):

- **Параметры** (основные):
  - `recombination_rate` (`RHO_HUMAN ≈ 1.6×10⁻⁹`),  
  - `mutation_rate` (`MU_HUMAN ≈ 1.25×10⁻⁸`),  
  - `demographic_events`: объект `msprime.Demography`,  
  - `number_intervals = 32`,  
  - `splitter = exponent_split`,  
  - `num_replicates`: число независимых реализаций генома,  
  - `lengt` (`L_HUMAN`): длина симулируемой последовательности (типично $3\times 10^7$ bp),  
  - `sample_size = 1`.

- **Шаг 1: Симуляция коалесцентного процесса**  
  `msprime.sim_ancestry(...)` генерирует `TreeSequence` с рекомбинациями.

- **Шаг 2: Наложение мутаций**  
  `msprime.sim_mutations(tree, rate=mutation_rate)` создаёт мутации;  
  формируются:
  - `mutations[0:len]`: бинарный вектор длиной `lengt`, 1 — мутация в данной позиции, 0 — отсутствие;
  - `d_times[0:len]`: индекс интервала коалесцентного времени для каждой позиции;
  - `prior_dist[0:32]`: априорное распределение по интервалам (доля позиций, попавших в каждый интервал).

- **Шаг 3: Агрегация / фильтрация по окнам (опционально)**  
  - `genome_postproccessor`: напр. `do_filter`, который агрегирует мутации по окнам длиной 100 нуклеотидов
    (берётся максимум в окне → вектор длины `lengt/100`).  
  - `times_postproccessor`: аналогичная агрегация для `d_times` (мода по окну).

- **Выход `DataGenerator.__next__`**:
  - В зависимости от флагов:
    - `(genome_postproccessor(mutations), prior_dist, times_postproccessor(d_times))`,  
    - или `(genome_postproccessor(mutations), times_postproccessor(d_times))`,  
    - или `(genome_postproccessor(mutations), prior_dist)`.

В типичной постановке обучения для `deepgene` используется связка:

- **Вход `X`**:  
  - тип: список/массив `int`, затем `torch.Tensor`,  
  - размерность после коллейта: `X ∈ ℝ^{B × L'}`  
    (где $L' = L_\text{HUMAN} / 100$ — число окон, `B` — размер батча).  
  - значение: 0/1 — отсутствие/наличие мутаций в окне.

- **Цель `Y`**:  
  - либо вектор классов `y[i] ∈ {0,…,31}` — индекс интервала (`times_postproccessor(d_times)`),  
  - либо вектор распределения `prior_dist[k]` по интервалам.  
  - после коллейта: `Y ∈ ℝ^{B × L'}` (для классификации по классам) или дополнительное измерение для распределений.

#### 3.4. Обёртка в `DatasetXY`

Класс `DatasetXY` (`deepgene/data/data.py`) принимает три генератора (train/val/test) и создаёт `DataLoader`-ы:

- **Формат батча**:
  - `collate_xy(batch)`:
    - `X`: список `Tensor[genome_length]` → `Tensor[B, genome_length]`,  
    - `Y`: список `Tensor[genome_length]` → `Tensor[B, genome_length]`.  
  - Модели (`GruLabeler`, `LstmLabeler`, `ReformerLabeler`) ожидают на вход именно `Tensor[B, L']`.

### 4. Пайплайн обучения (через `main.py`)

#### 4.1. Конфигурационные файлы (`gin`)

`main.py` использует три типа конфигов:

- **`model.gin`**: архитектура модели (`GruLabeler`, `LstmLabeler`, `ReformerLabeler`, тип embedding, размерности, тип loss и т.п.).  
- **`data.gin`**: параметры генератора данных (`DataGenerator` / `get_liner_generator` и др., длина генома, тип демографии, число реплик и т.п.).  
- **`train.gin`**: параметры обучения (`pytorch_lightning.Trainer`: число шагов, логирование, чекпоинты, использование GPU и т.д.).

Запуск обучения/теста:

- `python main.py --model=configs/.../model.gin --data=configs/.../data.gin --train=configs/.../train.gin fit`  
- `python main.py --model=... --data=... --train=... test`

#### 4.2. Архитектуры моделей

Общий формат вывода моделей:

- **Вход**: `X ∈ ℝ^{B × L'}` — бинарный профиль мутаций.  
- **Выход**: `logits ∈ ℝ^{B × L' × K}`, где $K = 32$ — число временных интервалов.

Модели:

- **`GruLabeler`**:
  - embedding (`ConvEmbedding` или `NoEmbedding`),  
  - двунаправленный GRU над осью генома,  
  - `Predictor` даёт logits по классам на каждом положении,  
  - набор потерь: CrossEntropy, KLDiv, EMD², CDW_CE и др.

- **`LstmLabeler`**:
  - embedding,  
  - двунаправленный LSTM (4 слоя, `hidden_size = n_class`),  
  - predictor,  
  - аналогичный набор потерь (CE, KL, EMD²).

- **`ReformerLabeler`**:
  - основан на `transformers.ReformerModel`,  
  - использует аксиальное позиционное кодирование (`axial_pos_shape`),  
  - вход паддится/обрезается до требуемой длины,  
  - дальше embedding → Reformer → predictor → обрезка обратно до исходной длины.

#### 4.3. Оптимизация и логирование

- Оптимизатор: `Adam` с `learning_rate` и `weight_decay` из конфига.  
- Потери выбираются строкой в `gin` и маппятся на соответствующие реализации из `deepgene.loss`.  
- Для логирования и мониторинга используется `comet_ml` (см. импорты в `main.py` и утилитах).

### 5. Пайплайн `mark_all.py` (оценка моделей и формат `result.json`)

Скрипт `mark_all.py` выполняет массовую оценку сохранённых чекпоинтов моделей и сохраняет результаты в иерархии директорий:

- Входные параметры (основные):
  - `--input_dir`: директория с поддиректорией `model/`, содержащей `.ckpt` файлы,  
  - `--model_type`: `gru`, `lstm` или `reformer`,  
  - `--output_dir`: корневая директория для результатов (по умолчанию `{input_dir}/results`),  
  - `--device`: `auto/cuda/cpu`,  
  - `--real_data`: флаг расчёта на реальных данных (см. раздел 6),  
  - `--allow_mixed`: разрешить присутствие чекпоинтов разных архитектур в `model/` (будут отфильтрованы по типу).

#### 5.1. Организация эксперимента

Для каждого чекпоинта модели:

- Определяется фактический тип архитектуры по содержимому state_dict (`detect_model_type_from_checkpoint`),  
- Загружается соответствующая модель через `load_model`, с установкой:
  - имени модели,  
  - функции потерь (CE/KL по имени файла),  
  - длины последовательности и путей к `gin`-конфигам (`data_universal.gin`, `train_universal.gin`, `model_*.gin`).

Далее для каждой демографии:

- **Список демографий**: `dems_name = ["const", "hl", "zigzag"]`.  
- Для каждой демографии `dname`:
  - генерируется объект `demography = load_dem(dname)` (через функции из `data_gen_np.py`),  
  - симулируется выборка:
    - `sequence_length = L_HUMAN = 3,000,000`,  
    - `num_replicates = 100`,  
    - `discrete_genome = True`,  
    - `end_time = dgn.limits[-1] + 1`.
  - для каждого репликата:
    - симуляция мутаций (`sim_mutations`),  
    - формирование бинарного массива мутаций `mutations[0:L_HUMAN]`,  
    - построение массива локальных временных индексов `d_times[0:L_HUMAN]` через `exponent_split`,  
    - фильтрация мутаций: `mutations → do_filter(mutations)` (агрегация по окнам 100 bp),  
    - подача блока вектора в модель:
      - `X = torch.tensor([mutations_filtered])`,  
      - `y_pred = model(X)` → `numpy`,  
      - `yy_pred = softmax(y_pred)`,  
      - `y_pred_classes = argmax(softmax, axis=-1)`.  
    - накопление:
      - глобального распределения `model_dist` по интервалам (`NN2pd_v2(yy_pred)`),  
      - глобального распределения `prior_dist` по интервалам (из `d_times`),  
      - полных массивов истинных и предсказанных индексов (`full_ground_true`, `full_predicted`),  
      - времени работы на репликат (`eval_time`).

В процессе создаются промежуточные графики:

- `NE_e.png`: восстановленная и истинная траектории $N_e(t)$,  
- `heatmap_e.png`: тепловая карта распределений по интервалам vs. истинный класс,  
  для разных сегментов внутри одного эксперимента.

#### 5.2. Финальные метрики и `result.json`

После обработки всех репликатов:

- Нормируются `prior_dist` и `model_dist` в распределения.  
- Строится:
  - матрица ошибок `confusion_matrix(full_predicted, full_ground_true)`,  
  - отчёт `classification_report` со средними метриками (включая `weighted avg`),  
  - интегральные ошибки по $N_e(t)$:
    - `Ne_pred`, `Ne_true`: траектории, восстановленные через функцию `from_probability_to_N(priors, limits)`,  
    - дополнительные меры ошибки, вычисляемые позднее (в `all_in_one.py`).

Создаётся JSON-файл `result.json` в директории:

- ` {output_dir}/{model_type}/{model_name}/{dem_name}/result.json`

**Схема `result.json`** (ключи и типы):

- **`model_name`** (`str`): имя модели (из имени чекпоинта, без расширения).  
- **`model_path`** (`str`): полный путь к `.ckpt` файлу.  
- **`dem_name`** (`str`): имя демографии (`"const"`, `"hl"`, `"zigzag"`).  
- **`model_dist`** (`List[float]`, длина 32): нормированное распределение модели по интервалам.  
- **`prior_dist`** (`List[float]`, длина 32): истинное распределение по интервалам, полученное из симуляции.  
- **`Ne_pred`** (`List[float]`, длина 32): восстановленная траектория $N_e(t)$ по предсказанию модели.  
- **`Ne_true`** (`List[float]`, длина 32): истинная траектория $N_e(t)$, соответствующая `prior_dist`.  
- **`confusion_matrix`** (`List[List[int]]`, размерность `32×32`): матрица ошибок по классам интервалов.  
- **`eval_time`** (`List[float]`): массив времен (в секундах) на обработку отдельных репликатов.  
- **`precision`** (`List[float]`, длина 32): **precision** по каждому классу (One-vs-Rest).  
- **`precision+-1(@3)`** (`float`): «смягчённая» precision с допуском в ±1 интервал при окне `k=3`.  
- **`precision+-2(@5)`** (`float`): аналогично, с допуском ±2 интервала при `k=5`.  
- **`recall`** (`List[float]`, длина 32): **recall** по каждому классу.  
- **`f1`** (`List[float]`, длина 32): **F1** по каждому классу.  
- **`cls_report`** (`dict`): полный отчёт `classification_report` из `sklearn`, содержащий:
  - метрики по классам,  
  - агрегаты (`macro avg`, `weighted avg`, `accuracy` и др.).

Эти файлы далее агрегируются скриптом `all_in_one.py`, который вычисляет интегральные ошибки (FMSE, RMSE, FMAE, FMAE2, `full-error`) и средние классификационные метрики по демографиям и моделям, а затем сохраняет сводный `final_result.json`/`xlsx`.  
`make_latex_table.py` конвертирует этот итоговый `final_result.json` в LaTeX-таблицы с заданным порядком столбцов и доверительными интервалами для метрик.

### 6. Оценка на реальном геноме

В `mark_all.py` реализована функция `mark_real_data`, которая позволяет тестировать обученную модель на реальных данных:

- **Входные данные**:
  - `real_data_files = ["real_data/NA20504_22chr.txt"]`: файл с позициями мутаций (по одному положению на строку) для отдельной хромосомы (например, chr22 индивида NA20504).  
  - `lenght_chr22 = 52_000_000`: длина хромосомы, задающая размер бинарного массива.

- **Предобработка**:
  - строится бинарный массив `mutations[0:lenght_chr22]`, где `mutations[pos] = 1`, если в файле есть мутация в позиции `pos`;  
  - вызывается `do_filter(mutations)` — агрегация по окнам 100 bp → вектор длины `lenght_chr22 / 100`.

- **Оценка моделью**:
  - используется готовая нейросеть `model`, загруженная для соответствующего чекпоинта;  
  - геном разбивается на блоки длиной 30 000 позиций (по аггрегированным окнам);  
  - для каждого блока:
    - формируется `X = torch.tensor([block])`,  
    - вычисляется `y_pred = model(X)`,  
    - берётся распределение `yy_pred = softmax(y_pred)`,  
    - через `NN2pd_v2` получается вклад блока в глобальное распределение `model_dist`,  
    - распределения по блокам суммируются и в конце нормируются.

- **Выходные артефакты**:
  - `NE_{sample}.png`: восстановленная траектория $N_e(t)$ для всего реального генома,  
  - `heatmap_{sample}.png`: тепловая карта предсказаний по интервалам вдоль генома.

Это обеспечивает сопоставимость архитектур, обученных на симуляциях, с реальными данными (включая PSMC-подобные траектории, если они доступны для сравнения).

### 7. Краткое саммари (текст для научной статьи)

Ниже приведён компактный текст, описывающий схему данных и пайплайн, пригодный для вставки в раздел *Methods*.

> В работе мы использовали библиотеку **DeepGene** для восстановления демографической истории популяции по паттернам мутаций вдоль генома.  
> Геномные данные моделировались при помощи `msprime` под различными демографическими сценариями (постоянная численность, «человеко‑подобная» история, зигзагообразные и смешанные траектории), после чего для каждой позиции генома рассчитывались локальные коалесцентные времена и биннировались в $K=32$ экспоненциально масштабированных интервалов.  
> В качестве входа нейросетевых моделей (двунаправленные GRU/LSTM и Reformer) использовались бинарные профили мутаций, агрегированные по окнам фиксированной длины, а в качестве целевой переменной — либо индекс временного интервала для каждой позиции, либо соответствующее распределение по интервалам.  
> Обучение проводилось в фреймворке `pytorch_lightning` с использованием конфигурационных файлов `gin` для описания архитектуры, данных и режима обучения, а качество моделей оценивалось на независимых симулированных наборах при помощи матриц ошибок, метрик классификации (accuracy, precision, recall, F1) и интегральных ошибок по восстановленной траектории эффективной численности $N_e(t)$.  
> Отдельный сценарий `mark_all.py` осуществляет массовую оценку всех обученных чекпоинтов на наборе фиксированных демографий, формируя стандартизированные JSON‑отчёты, которые далее агрегируются в сводные таблицы; в рамках того же сценария реализована оценка на реальных данных (например, хромосома 22 человека), где по наблюдаемому профилю мутаций строятся нейросетевые оценки $N_e(t)$ и соответствующие тепловые карты распределений по интервалам.
